En-tête de module et import

space outils::calcul;
use core::types::option::{Option, option_some};
use outils::conversion as conversion;

space accepte un chemin. use peut importer un module ou un chemin, définir un alias avec as, importer un groupe de noms entre accolades ou demander un glob avec *. Les noms qualifiés utilisent ::. La résolution concrète dépend de la racine du projet et des chemins de modules configurés.

Valeurs et types nommés

export const REPONSE: i64 = 42;
static LIMITE: i64 = 42;
type Identifiant = u64;
opaque Jeton;

const déclare une valeur constante de module. static réserve un stockage de module immuable ; ajoutez mut après static pour autoriser les écritures, par exemple static mut COMPTEUR: i64 = 0;. Un alias type Nom = Type est transparent : il peut être utilisé dans les annotations, les paramètres et les retours comme le type cible. opaque Nom; déclare un type sans exposer sa représentation. Les pointeurs vers ce type sont utilisables, mais son emploi par valeur et les déclarations opaques génériques restent hors de la couverture validée.

Formes et choix

form Point {
    x: i64,
    y: i64,
}

pick Etat {
    Inactif,
    Pret,
    Erreur(i64),
}

Une form contient des champs nommés. Un pick décrit des variantes, et la grammaire permet de placer des types entre parenthèses après une variante. Dans le langage courant, on emploie souvent les formes comme valeurs composées et les choix pour représenter des états exclusifs.

Procédures

export proc ajouter_un(valeur: i64) -> i64
    requires valeur < 100;
    ensures result == valeur + 1;
{
    return valeur + 1;
}

Une procédure peut déclarer des paramètres typés, un type de retour, des paramètres génériques, une clause where et plusieurs contrats requires/ensures. Le corps est un bloc. Les paramètres n’ont pas de valeur par défaut dans la grammaire actuelle.

Traits et implémentations

Un trait contient des déclarations liées à un contrat de comportement. Un impl regroupe les déclarations d’implémentation pour un type et éventuellement un trait. Les méthodes peuvent employer &self ou &mut self ; la bibliothèque core en fournit des signatures. La liaison effective des implémentations de traits et le dispatch générique ne sont pas complets dans le compilateur d’après la documentation de core.

export trait Display {
    proc fmt(&self, formatter: &mut Formatter) -> bool;
}

Attributs

Le bootstrap traduit #[cold], #[hot], #[noinline], #[deprecated] (avec ou sans message) et #[must_use] sur les procédures ; #[thread_local] reste réservé aux statiques. #[doc("...")] est conservé comme métadonnée sans modifier le code généré. Un attribut inconnu, contradictoire ou placé sur une déclaration incompatible est rejeté par le backend C17. Les indications d’optimisation et les avertissements suivent les capacités du compilateur C hôte.

Frontières, macros et tests

  • extern "bibliotheque" proc nom(...); déclare une procédure dont le corps est fourni à l’extérieur.
  • intrinsic nom(...); déclare une fonction fournie par le compilateur ou le runtime ; un symbole hôte absent provoque une erreur d’édition de liens.
  • macro nom(param: Type) { ... } définit un modèle développé par le bootstrap avant l’analyse syntaxique. Appelez-le avec nom!(argument) ; les arguments sont substitués comme des séquences de jetons, puis le code développé passe par l’analyse normale. La récursion est limitée et les noms générés ne sont pas hygiéniques ; cette fonctionnalité reste expérimentale.
  • test "nom" { ... } déclare un bloc exécuté comme point d’entrée lorsque le fichier ne définit pas main. En présence de main, les tests ne sont pas exécutés par run.

Les modificateurs prévus avant une déclaration comprennent pub, export, async, unsafe et comptime. Un appel async produit une tâche différée qui peut être stockée dans une variable. Son corps ne s’exécute qu’au premier await ; le résultat est conservé et les attentes suivantes ne relancent pas le corps. Cette exécution reste synchrone : la tâche n’est pas suspendue au milieu de son corps, aucun ordonnanceur ne fait progresser plusieurs tâches et aucune concurrence n’est créée. Dans le bootstrap 0.1.1, les appels directs à une procédure comptime sont évalués pendant la génération C17 lorsque leurs arguments sont constants et que leur corps utilise les formes prises en charge : paramètres scalaires i64, u64 ou bool, opérations arithmétiques et logiques, variables locales immuables et appels directs à d’autres procédures comptime. Les procédures génériques, asynchrones, unsafe, les méthodes de trait/impl et main, les clauses contractuelles et les expressions non évaluables échouent avec E0902. Les appels directs à une procédure unsafe doivent se trouver dans une procédure unsafe ou un bloc unsafe { ... } ; sinon, le bootstrap signale E1301. La vérification ne couvre pas encore les appels via pointeur de fonction ni la sûreté mémoire, les alias ou les durées de vie. Ces formes restent expérimentales.
